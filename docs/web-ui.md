# Веб-панель Bender

Исходник дизайна, мобильной вёрстки и клиентской логики:
`BendeRadio/webui/index.html`. Он работает без внешних ресурсов и интернета.
После изменения выполнить `python agent-tools/build_webui.py`, затем собрать
прошивку. Полученный `BendeRadio/WebUiPage.h` включён в проект; вручную его не менять.

Разделы: FM / Радио, Настройки, Характер. В характере пять регуляторов 0–100:
сарказм, общительность, любопытство, упрямство и теплота. Пресеты:
Классический, Добряк, Ворчун, Исследователь, Спокойный. Пресет выставляет
ползунки, ручная настройка определяет «Свой микс», сброс возвращает классику.

Формы POST `/save` передают `section`: `radio`, `behavior`, `display`, `wifi`, `ai`, `character`.
Обработчик проверяет поля перед записью и сохраняет только соответствующую группу.
Старые полные формы без `section` поддерживаются. Сохранение перезапускает плату;
другие несохранённые формы при этом теряются, о чём сообщает страница.
`/calib` остаётся предпросмотром яркости без записи в NVS.

Характер сохраняется одним пятибайтовым значением NVS `character_v1`.
Все пять полей обязательны, допустимы целые числа 0–100; неполный запрос
ничего не меняет. Старые формы без `section` характер не затрагивают.
При подключении прошивка отправляет `session.character` только локальному
AI серверу. Нужны новая прошивка и перезапуск обновлённого `local_server/server.py`.
В логе сервера строка `[Character]` показывает принятые значения.

Эквалайзер заменяет прежний общий `bender_level` для клиентов с `character`.
Сервер меняет системные инструкции; смена профиля сбрасывает удалённую цепочку
Grok со старым характером, перенося ограниченную локальную историю в новую.
Обычный reconnect с тем же профилем цепочку не сбрасывает. Персональная память,
голос TTS, команды и готовые реакции на события от эквалайзера не меняются.
Сервер, как и раньше, рассчитан на один Бендер с общими настройками и историей.

## Проба характера

Кнопка в эквалайзере озвучивает ответ на один и тот же вопрос:
«Бендере, як проведемо цей вечір?» Используются текущие, в том числе
несохранённые, ползунки. Результат звучит на колонке через обычный тракт TTS.
Надпись меняется по преобладающей черте; грубый вариант требует сарказма и
упрямства от 80 при теплоте ниже 35. У кнопки постоянное доступное имя.

POST `/character/preview` принимает все пять черт, возвращает 202 либо ошибку;
GET того же адреса возвращает состояние: 0 — не запускали, 1 — подключение,
2 — генерация, 3 — воспроизведение, 4 — завершено, 5 — ошибка/отмена.
Запрос идёт из WebUI в очередь сетевой задачи, а не прямо в WebSocket из HTTP.
Сетевое событие `character.preview` содержит `character` и `request_id`;
сервер отвечает обычным потоком аудио и `character.preview.result` с `ok`.
Тест не пишет NVS, персональную память или историю; запрос модели отдельный,
без `previous_response_id`, для Grok также `store=false`.

Во время теста повторное нажатие и сохранение характера заблокированы в UI.
Занятость, нулевая громкость, отсутствие Wi-Fi, AirPlay/BT возвращают объяснение.
PTT/переключение источника может отменить пробу. Сервер ограничивает ожидание
генерации/синтеза 38 секундами; старая версия сервера приведёт к таймауту.
Каждое нажатие вызывает один дополнительный запрос к настроенной модели.
Нужны обновление прошивки и перезапуск локального сервера.

HTML передаётся частями из flash. Пользовательские строки экранируются и не
обрабатываются повторно как шаблон. Пустые подстановки не отправляют HTTP-чанк:
пустой чанк означает завершение ответа. Полная страница не копируется в String.

Проверки:
- `tests/webui_scope_test.cpp` — независимость областей сохранения, старые формы.
- `tests/test_webui_template.py` — поля форм, уникальные ID, подстановки, отсутствие
  внешних ресурсов, соответствие исходника встроенному шаблону.
- `tests/test_character.py` — валидация протокола, влияние каждой черты на промпт,
  отсутствие конфликта со старым уровнем грубости и обновление цепочки диалога.
- `python agent-tools/preview_webui.py` — локальный макет с вымышленными настройками.
- `python agent-tools/check_webui_browser.py` — изолированный headless Chrome:
  навигация, ползунок, сброс, форма поведения, яркость, вёрстка при 320/390 px.
  Снимки и результаты сохраняются в `artifacts/webui-preview`.

Браузерные проверки используют локальный макет и не отправляют команды колонке.
После прошивки нужна проверка сохранения настроек и предпросмотра на самой плате.
